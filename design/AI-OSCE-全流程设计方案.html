01问题与设计公理

先把"为什么难"说清楚，否则所有设计都会退化成功能堆叠。

OSCE 的三个结构性痛点

OSCE 的困境不是"效率低"，而是三个互相纠缠的结构性问题：

反馈延迟

一次终结性 OSCE 的反馈往往滞后数周至数月。等到学生拿到评分表，临床轮转早已结束，形成性价值几乎归零。学生需要的是"刚才那句话为什么扣分"，而不是"上学期你沟通项偏低"。

专家负荷

命题、SP 培训、现场评分、复核、申诉处理，全部压在少数临床教师身上。负荷的直接后果是评分趋中、行为锚被简化、边缘案例草率判定——恰恰是最需要精细判断的地方最粗糙。

标准化幻觉

OSCE 承诺"客观结构化"，但 SP 每次扮演略有不同、考官宽严不一、站间难度漂移。标准化是目标而非事实，而传统手段（培训、校准会）只能压低方差，无法测量方差。

AI 的三个诱惑

面对这三座山，AI 提供的诱惑是"全自动"。但评分表可靠性不足、SP 人格会漂移、模型会编造证据——全自动 = 不可申诉。设计的核心不是拒绝自动化，而是精确划出自动化的边界。

五条设计公理

后续所有模块设计都可以从这五条推导出来。它们不是价值观宣言，而是会直接决定接口形态和代码结构的约束。

公理含义对设计的直接约束
A1 权限随风险递减 AI 的自主度不是一个全局开关，而是每个环节、每个评分项各自的属性。 系统必须支持项级（rubric item 级）的 AI 权限配置，而非站级或系统级。
A2 证据先于结论 任何 AI 给出的分数，必须能回溯到一段可播放、可定位的原始素材。 评分数据结构强制包含 evidence_span；无证据的分数在 schema 层就无法写入。
A3 单一真相源 命题、SP 对话、评分、反馈必须共用同一套评分表语义。 评分表是上游驱动而非下游产物，见第 4 节"评分表即协议"。
A4 人类保留否决权 AI 可以建议、排序、初筛，但不能成为高利害结果的最终裁决者。 存在不可绕过的 human_signoff 状态；缺它则成绩不可发布。
A5 闸门式放行 能力上线靠量化门槛，而不是"专家看过觉得可以"。 每个 AI 能力有 release_stage 与 exit_criteria，未达标自动降级到人工全量。
设计推论

把 A1 + A3 放在一起，会得到一个不太直觉但很关键的结论：AI 权限的最小粒度必须是评分项，而不是考站。同一个站里，"洗手"这种行为锚清晰、视频可验的项可以让 AI 独立判定；而"职业素养/共情"这种高度依赖情境判断的项，即使同站也必须人工主导。一刀切按站定级，要么浪费 AI 能力，要么放过风险。

与现有框架的关系

本方案沿用"5 个 AI 角色 + 4 个治理支柱"的功能骨架（学习支持、AI 标准模拟患者、评估支持、案例生成、学习分析 × 人的监督、透明度、伦理与安全、可追溯性），但在两处做了工程化推进：

  • 从"角色"推进到"权限矩阵"：五个角色是功能视角，本方案补充了每个角色在各环节的权限等级与不可逾越边界，使其可以直接落成配置表。
  • 从"治理原则"推进到"闸门指标"：四个支柱各自对应可采集的指标与自动降级规则，避免治理停留在文档层。

02风险分级模型

整套系统的"宪法"。先定级，再谈功能。

分级不看技术难度，只看两个变量：结果对考生的利害程度，以及错误被发现与纠正的成本。二者共同决定 AI 能走多远。

等级典型场景 AI 权限边界人类保留失败后果
L0 内部 草稿生成、素材检索、题干润色、教师内部工具 AI 可自主完成，无需逐条审核；输出仅在校内工作台可见，带"未审核"水印。 发布前一次性确认 返工，无外部影响
L1 形成性 学生自主练习、同伴角色扮演实时反馈、错题重练 AI 主导评分与反馈；按 10% 随机抽样做离线审计，不阻塞学生即时看到结果。 抽样审计、投诉即全量复核 学生被误导，可通过后续教学纠正
L2 模拟考 校内模拟 OSCE、课程形成性考核、A/B 对照研究 AI 初评 + 证据提取；低分尾部与低置信项强制人工；其余抽检 20%。 边缘案例裁决、成绩确认 教学决策偏差，影响分组与辅导资源

关键约束

同一场考试内，等级只能向上调整，不能向下。一旦某站因异常被提升为 L3 处置（如发现 AI 证据缺失），该站本场次全部记录进入全量人工复核，且该调整写入审计日志并计入当次考试的质量报告。这条规则防止"出问题就降级"的组织性掩盖。

六层结构，中间两层是设计重点：能力网关 + 流程编排。

三个架构决策及其理由

决策一：AI 能力网关是唯一出口，业务层不得直连模型

原因有三。其一，可追溯性要求"每一次模型调用都能被定位到具体版本"，散落的 SDK 调用无法保证这一点。其二，高利害场景需要一键降级——网关层可以把"AI 评分"整体切到"仅证据提取"，业务层无感。其三，成本与配额必须集中计量，否则无法回答"这套系统到底多少钱一站"。

网关的最小接口契约：

POST /gateway/invoke所有 AI 调用的唯一入口
{
  "capability": "score.suggest",        // 能力名，非模型名
  "release_stage": "simulation",      // 当前闸门阶段，决定可用能力集
  "subject_ref": { "attempt_id": "att_8842" },
  "inputs": { "rubric_version": "rb_2026_11_07", "media_uris": ["...] },
  "constraints": { "max_latency_ms": 3000, "require_evidence": true },
  "idempotency_key": "att_8842:rb_2026_11_07:score:v1"
}
// 响应强制包含 model_version / prompt_version / 耗时 / 成本 / 证据链

require_evidence: true 是硬约束：如果模型无法定位到具体时间片段，网关直接返回拒答而不是低质量答案，由业务层降级到人工。这比"允许 AI 猜"要安全一个数量级。

决策二：流程状态机外置，不依赖 LLM 记忆

AI 模拟患者最容易出问题的地方，是把"该说什么"和"怎么说"混在一次生成里。本方案把二者拆开：对话状态（已释放哪些信息、当前处于哪个阶段、还剩多少时间）由确定性状态机维护；LLM 只负责把当前该释放的信息自然地说出来。这直接消解了幻觉泄露与人格漂移的根源，详见 6.1。

决策三：媒体与评分分离存储，用引用而非拷贝

音视频体积大、留存期长、涉及隐私，而评分记录需要长期可读。二者生命周期不同，混存会导致"为了保住成绩不敢删视频"或"清理视频把证据链一起毁掉"。设计上用 evidence_span 保存 {media_id, start_ms, end_ms, transcript_hash}，媒体按策略归档，成绩记录永久保留且可通过哈希校验完整性。

部署形态建议

教学场景（L0–L1）可用公有云 API 模型以压低成本；涉及真实考生音视频的 L2–L3 场景，建议私有化或专有云部署，且 ASR 与评分模型不出院/校网。这条不是合规洁癖——真实考场音视频包含可识别的患者信息与考生表现，一旦出境或进入第三方训练语料，申诉与舆情风险不可控。

04评分表即协议

整套设计的主骨架：把 rubric 从"终点产物"变成"全链路的类型定义"。

传统的流水线是：写病例 → 写 SP 脚本 → 写评分表 → 考 → 评分 → 反馈。评分表在链条末端才出现，于是 SP 演的和考官评的往往是两套逻辑，学生的反馈又是第三套语言。

本方案把它反过来：先定义可观测的行为，再由行为反推剧情与对话。评分表成为唯一的"契约"，其余产物都是从它派生出来的。

一个 rubric item 的四元组

关键的工程改动是：评分项不能只是"一句话 + 分值"，它必须携带足够的信息，让系统能自动派生出下游产物。因此每个 item 定义为四元组：

RubricItem — 最小契约单元schema v2
{
  "item_id": "HX.03",
  "domain": "history_taking",
  "anchor": {                                  // ① 行为锚：可观测、可判定
    "observable": "询问胸痛的放射部位与持续时间",
    "positive": "主动询问放射至左臂/下颌，并追问持续时间",
    "partial": "仅询问其一，或需二次追问才涉及",
    "negative": "未询问放射或持续时间"
  },
  "evidence_type": "utterance",          // ② 证据形态：决定谁来判
  "phase": "information_gathering",     // ③ 对话阶段：决定何时该触发
  "weight": 2,
  "ai_authority": "suggest",             // ④ 权限：none | extract | suggest | decide
  "critical": false,                        // 关键项：错判即触发人工强制复核
  "guideline_ref": "ESC-ACS-2023 §3.2"
}

四个字段各自驱动一条下游链路，这就是"协议"的含义：

字段驱动什么具体机制
anchor 生成 SP 的信息槽与触发条件 正向锚中出现的临床信息（"放射至左臂"）自动成为患者需持有的信息槽；只有被问及时才释放。锚写不清 → 信息槽无法生成 → 命题阶段就报错。
evidence_type 决定证据采集方式与 AI 可达权限上限 utterance 走音频转写；action 走视频/器械日志；document 走笔记 OCR；global 只能人工。系统据此自动封顶 AI 权限。
phase 构建对话状态机的阶段与检查点 四阶段（开场准备 → 信息采集 → 评估 → 计划与结论）各设"必须触发项"清单；SP 在阶段末若发现关键信息槽未被问及，可自然引导（"医生，我还有点担心……"）而非静默漏考。
ai_authority 评分工作台的交互形态与路由规则 extract：只高亮证据，不打分；suggest：给分 + 置信度，人确认；decide：可直接入分（仅限 L0/L1 且行为锚为布尔型）；none：不进入 AI 管道。

与 LLM 生成评分表的关系

现有证据很明确：LLM 生成的站包在沟通行为、EPA 对齐上评分尚可（约 4.6/5），但评分表可靠性是明确短板，指南一致性维度得分最低且评分者分歧最大。因此本设计的定位是：

  • LLM 产出 anchor.positive/partial/negative 的初稿，并强制标注它引用的指南条款（guideline_ref）；
  • 系统对每条 anchor 做可观测性检查：是否包含可被判定的动词与可听/可见的对象。含糊表述（"表现出同理心"）自动标红，不允许进入冻结；
  • 专家只做三件事：改写行为锚、核验指南一致性、校准难度。不做从零编写。

这把人工审核资源从"写整站"压缩到"改三类节点"，也正是设计建议中"AI 初稿 + 结构化人工精修"的具体落地形态。

色带为环节的默认风险级；实际等级按场次用途（练习/模拟/终结）动态判定，取二者较高者。

1
蓝图与命题
把能力要求翻译成可考的站
L0 内部草稿

这一阶段的产出不允许直接进入考试。它的唯一价值是把"空白页面"变成"可修改的初稿"，把专家的时间从打字转移到判断。LLM 在这里是最安全的——错了只是返工。

输入
培养目标 / 里程碑 · EPA 清单 · 既往站包库 · 临床指南 · 上次考试的质量报告（哪些站区分度低）
输出
站包草案 v0.1：考生指令、SP 脚本骨架、rubric 草案（含指南引用）、建议时长与权重
AI生成与检查
  • 蓝图覆盖度分析：哪些能力域本年度未被任何站覆盖、哪些过度重复
  • 站包初稿：题干 + 指令 + 脚本 + rubric 一体化生成，每条锚必须附指南条款
  • 难度预判：依据历史站包的特征向量（信息密度、干扰项数、时间压力）给出难度区间
  • 去重：与既往站包的语义相似度检索，避免"换汤不换药"
人保留决策
  • 蓝图审批：考什么、不考什么，是教育判断，不可外包
  • 临床真实性把关：LLM 倾向生成"教科书病人"
  • 删除不合理设定（不符合本院流程、超出学生层级）
  • 确认站的组合能构成有效的能力抽样
典型失败模式教科书式病人：症状典型、信息齐备、无共病无干扰。后果是区分度极低——好学生和差学生都能问对。对策：在生成提示中强制配额（至少 1 项共病、1 项与主诉无关的合理诉求、1 处主诉模糊），并在 S2 用历史区分度数据反查。

站包精修与冻结
把草案变成不可变的契约
L2 模拟考

这是整套流程中人工密度最高的一步，也是最值得投入的一步。因为冻结之后的一切——SP 怎么演、AI 怎么评、学生看到什么反馈——都由它决定。

输入
站包草案 v0.1 · 专家批注 · 历史难度与区分度数据
输出

系统强制执行的四项检查

检查判定规则不通过时
可观测性行为锚必须含"可被判定的动词 + 可听/可见的对象"。禁止"理解""具备""表现出良好…"标红阻断冻结，必须改写
可达性每个 rubric 项的信息源必须存在于 SP 的信息槽中。考生问不到的信息不能成为考点自动补齐信息槽，或建议删除该项
指南一致性guideline_ref 必须能在知识库中检索到原文，且语义匹配降级为"待核验"，由专家人工确认
三方一致题干承诺的考点 ⊆ 脚本可提供的信息 ⊆ rubric 评的内容输出差异清单，逐条裁决
AI检查与建议
  • 四项自动检查 + 差异定位（精确到句子）
  • 行为锚改写建议（把"同理心不足"改写为可观测表述）
  • 难度校准：对比同类站的历史通过率，提示"预计过难/过易"
  • 生成四类派生资产并做交叉校验
人保留决策
  • 改写行为锚——这是不可委托的核心工作
  • 核验指南条款的适用性（同一指南在不同层级有不同推荐强度）
  • 设定及格线与关键项（critical item）
  • 签字冻结，并对该版本负责
典型失败模式评分表"看起来合理但不可判"。例如"能建立良好医患关系"——三位考官会给出三个答案，且都自认为正确。这类项在冻结阶段必须被拦下，否则它会在评分阶段变成永久的争议源，并在申诉时成为机构的软肋。
3
SP 构建与认证
让"同一个人"可以重复出现
L1 练习L2 模拟

这里需要做一个明确的取舍：AI 模拟患者先用于练习与模拟考，不急于进入高利害终结性考试。理由不是技术不成熟，而是高利害场景下"SP 表现本身"就是公平性的一部分，一旦 AI 出现人格漂移，无法像真人 SP 那样在事后被召回作证。

输入
冻结版 SP 脚本 · 信息槽清单 · 教学目标（该站要训练什么沟通难点）
输出
人格卡（版本化）· 对话状态机配置 · 红队测试报告 · SP 认证记录

人格卡的五维结构

单一"性格"描述不足以覆盖真实教学需求，也无法被稳定复现。人格卡需要多维且可量化：

维度取值示例为什么需要它
性格与情绪基调焦虑 / 克制 / 易怒 / 依赖；情绪唤起阈值 0–1决定面对不同提问风格时的反应差异
语言熟练度母语流利 / 方言口音 / 有限普通话 / 医学词汇不理解训练"跨语言沟通"这一真实能力
病史记忆水平清晰 / 部分模糊 / 需提示才能回忆控制信息释放的难度，防止"一问全给"
认知混乱度0（清晰）– 1（谵妄倾向，答非所问）老年/急症站的核心考点
披露阈值主动 / 需直接询问 / 需建立信任后才说 / 永不主动直接决定"共情"类评分项能否被触发
AI构建与自检
  • 从脚本与信息槽生成人格卡初稿
  • 配置对话状态机（阶段、检查点、引导语）
  • 红队自测：自动生成"诱导泄露""反复追问""沉默对抗""超时"等对抗性考生行为，检验是否泄露未授权信息
  • 跨会话一致性抽测：同一人格卡跑 20 次，比对关键信息释放顺序
人保留决策
  • 批准人格卡（尤其披露阈值——它决定考点能否成立）
  • 审定禁用话术（不承诺诊断、不给治疗建议、不评判考生）
  • 验收试演：真人扮演考生走一遍，判断"像不像"
  • 决定该 SP 是否可用于 L2 及以上
典型失败模式过度配合。LLM 的天性是"帮忙"，于是考生一句"你是不是胸口疼"就把全部病史倒出来——考点瞬间失效。技术上靠状态机的信息槽门控解决（见 6.1），管理上靠红队测试验收。

考务编排
在约束中求公平
L1 内部

排考看起来是纯运筹问题，但它直接影响公平性：如果某考生连续抽到三个最难的站，或某站在一天中的最后时段（考官疲劳期）集中出现，分数差异中就会混入与能力无关的方差。

输入
站包集合 · 考生名单与特殊需求 · 场地/设备/SP/考官可用时段 · 历史站间难度
输出
排考表 · 资源占用图 · 风险提示（疲劳段、设备冲突、SP 超时）
AI求解与预警
  • 约束求解排考（硬约束：设备/人员/时长；软约束：难度均衡、时段均衡）
  • 冲突检测与最小改动建议（改一个人而不是重排全场）
  • 疲劳与顺序效应预警：标记"同一考官连续评分 > 4 小时"的时段
  • 特殊需求适配（延长时长、单独通道、无障碍）
人保留决策
  • 确认软约束权重（公平 vs 效率的取舍是价值判断）
  • 审批特殊需求安排
  • 处理算法无法表达的人情因素（临时请假、场地突发）
典型失败模式贪心排考导致难度聚集。正确做法是把"每位考生的加权难度总和"作为约束而非目标——即保证所有人承受的难度期望相近，而不是让总体通过率好看。

稳定、公平、全程可回溯
L3 高利害

这个阶段 AI 的角色最需要克制。它应该是记录员与哨兵，不是裁判，也不是副考官。

输入
冻结站包 · 排考表 · 人格卡 · 设备状态
输出
音视频 · 带时间戳转写 · 事件日志 · 异常记录 · 完整性校验值

实时提示的红线

实施阶段最大的隐性风险是自动化偏见：一旦考官看到屏幕上"该生可能不合格"的提示，后续观察会被锚定，评分独立性消失。因此实时提示只允许呈现事实，禁止呈现判断：

允许（事实层）禁止（判断层）
"尚未观察到洗手动作""该生无菌操作不合格"
"距结束还有 2 分钟，以下 3 项尚无证据""该生可能无法通过本站"
"该考生语速较快，转写置信度偏低""该生沟通表现较差"
"设备 2 音频中断 8 秒，已标记""本段不计入评分"

并且提示必须可一键关闭，且关闭状态记入日志——用于事后分析"提示是否影响了评分"（比较开启/关闭组的分数分布）。

AI记录与预警
  • 实时流式转写（说话人分离、医学词表增强）
  • 异常检测：长时间沉默、情绪激烈、设备中断、超时未结束
  • 事实层提示（见上表），可按站配置开关
  • AI SP 对话（仅限练习与已认证的模拟场景）
人保留决策
  • 现场监考与秩序维护
  • 异常终止权：任何技术或伦理异常，人类可立即中止该站
  • 中断后的补偿判定（延时/重考/不计分）
  • 对 AI 提示的采纳与否，不做强制
典型失败模式技术故障无补偿机制。录像缺失 30 秒，评分照样进行，申诉时无法举证。设计对策：媒体完整性哈希在采集端实时计算，缺口即刻标记 integrity_gap，该站自动升级为"人工全量 + 现场记录补充"，并在成绩单上留痕。

L3 高利害

这是证据最成熟、投入产出比最高的环节，也是整套系统的心脏。核心不是"AI 能不能评准"，而是"当 AI 不确定时，系统知不知道它不确定，并把人放到那个位置"。

典型失败模式"全量 AI 评分 + 事后抽查"。看起来高效，实际上把风险推给了抽查没抽中的部分：一旦某位考生的分数是错的且未被抽中，错误就永久固化，而申诉时机构拿不出证据。正确做法是按风险路由而非按比例抽样——让"该被看的一定被看"。

反馈与质量分析
把"分数"变成"下一次怎么做"
L1 形成性

传统 OSCE 最大的浪费，是花了巨大成本采集的高质量行为数据，最后只输出一个分数。这些数据本可以支撑个人能力画像与站级质量改进两条回路。

输入
评分记录 + 证据链 · 历史多次成绩 · 群体数据
输出
个人反馈报告（含证据片段）· 能力雷达 · 站级难度/区分度/信度报告 · 教学改进建议

反馈的三段式结构

只说"沟通待加强"的反馈等于没反馈。每条扣分项必须生成三段：

Feedback Unit — 反馈的最小单元由 rubric item 派生
① 证据：发生了什么（可回放，不带评判）
  "02:14 你问：'疼多久了？' 患者回答后，你直接进入查体。"

② 行为：对应哪个评分项、差在哪一档
  "HX.03（放射部位与持续时间）：未询问放射，判定为 negative。"

③ 替代方案：下次可以怎么说（可执行）
  "可追加：'这种疼会不会窜到肩膀或下巴？' —— 一句话即可覆盖该评分项。"

第三段是最容易被忽略、也最有价值的。它把评分表从"审判工具"变成"教学工具"，这正是形成性评价的本质。

AI生成与分析
  • 三段式反馈生成（严格引用 evidence_span，禁止无据评价）
  • 跨站能力画像：把 12 个站的表现映射到 6 个能力域
  • 纵向趋势：与上次同类站对比，标出进步/退步
  • 站级心理测量：难度、区分度、项间相关、Cronbach's α
  • 异常站标记：某站全员满分或全员零分 → 疑似评分表或 SP 问题
人保留决策
  • 审核反馈语气（防止打击性表述；对不及格者需人工加一段鼓励）
  • 裁定"异常站"的处理：改评分表、改 SP、还是改教学
  • 把质量报告转化为下一年度的命题输入（闭环回到 S1）
典型失败模式反馈泛化。LLM 在没有强约束时会写出"建议加强沟通技巧，多与患者交流"这类放之四海皆准的话。对策：反馈生成器的输出必须包含至少一个时间戳与一句可直接背诵的替代话术，否则校验失败重写。

06三个核心机制的工程规格

这一节写给要动手实现的人。每个机制都给出数据结构、判定逻辑与兜底策略。

6.1 人格一致性控制器

问题的根源在于：如果让 LLM 在一次生成里同时决定"该说什么"和"怎么说"，它就会在两件事上同时犯错，而且错误相互掩盖——考生问了一个不该回答的问题，模型"体贴地"回答了，语气还很像那个患者，于是看起来毫无破绽。

解法是把这两件事物理分离：

  • "说什么"由确定性状态机决定。它维护信息槽（information slot）的释放状态，只依据考生的意图标签与当前阶段，不含任何生成能力，因此不可能幻觉。
  • "怎么说"由 LLM 决定。它拿到的是"本轮允许说出的槽内容 + 人格卡 + 最近 3 轮上下文"，任务被窄化为"把这几句话用这个人的方式说出来"。
  • "说得对不对"由独立验证器判定。验证器与生成器使用不同模型、不同系统提示、且看不到完整对话历史（只看人格卡 + 本轮草稿 + 允许槽），避免上下文污染导致的自我确认。

信息槽的结构

信息槽是这套机制的原子单位。它把"患者知道什么"与"什么时候可以说"编码成可判定条件：

InformationSlot — 信息槽由 rubric anchor 派生
{
  "slot_id": "S.07",
  "content": "胸痛会窜到左臂，大概持续二十分钟",
  "linked_items": ["HX.03"],          // 该槽对应哪些评分项
  "phase": "information_gathering",
  "disclosure": "on_direct_ask",        // active | on_direct_ask | on_trust | never
  "trigger": {
    "type": "any_of",
    "conditions": [
      { "intent": "ask_radiation" },
      { "semantic": "疼痛是否向其他部位扩散", "min_sim": 0.82 }

leak_guard 是最关键的一位。它在生成后对该槽的关键实体（"左臂""二十分钟"）做字符串与语义双重扫描，一旦出现在未被允许的回应中，直接判定泄露并拦截。这比指望 LLM"自觉不说"可靠得多。

单轮控制循环

controller.step() — 每轮对话python 伪代码
def step(user_text, st):
    intent = classify(user_text)                       # 规则优先，兜底小模型
    released = st.machine.release(intent, st.phase)    # 只返回槽 id 列表

    if not released and st.phase_should_advance():
        released = st.machine.advance(st.phase)        # 阶段推进时的自然过渡
        st.phase = st.machine.next_phase(st.phase)

    draft = generator.say(released, st.persona, st.last_k_turns(3))

    for attempt in range(2):
        v = verifier.check(draft, st.persona, allowed=released,
                           forbidden=st.machine.unreleased_slots())
        if v.total >= 0.85:
            return emit(draft, evidence=None)
        if v.repairable:
            draft = rewriter.fix(draft, v.violations)
        else:
            break

    return emit(safe_template(st.phase, released), degraded=True)

验证器的三项判据

判据检查内容权重不通过处理
人格保真语气、教育水平、情绪基调、口头禅是否与人格卡一致0.35可修正（改语气）
信息边界是否泄露未释放槽；是否编造病例未定义的信息（既往史、用药、家属）0.50不可修正，直接回退模板
临床合理是否与病例设定矛盾（时间线、症状组合、生命体征）0.15不可修正，回退模板并告警
为什么信息边界权重最高

人格漂移只是"演得不像"，影响体验与结构效度；而信息泄露直接摧毁考点——考生没问就得到了答案，该评分项失去区分能力，且这种失效在数据上表现为"该站全员满分"，很难在事后被发现。因此宁可牺牲对话自然度（回退到略显生硬的模板），也不能放行泄露。

跨会话一致性则靠三件事保证：人格卡版本化（同一场考试绑定同一 persona_version）、状态机确定性（同输入必同输出）、生成温度锁定在 0.6–0.7 并记录随机种子。这使"同一个人"在不同考生面前至少结构上是可比的。

人工界面的三条纪律

  • 默认播放，不默认给分。打开一条待复核记录时，界面首先自动播放证据片段（前后各留 3 秒），评分按钮才出现。这避免评分员先看到 AI 的分数再"找理由同意"。这是对抗自动化偏见最有效的一个界面细节。
  • 三元操作，拒绝自由输入。只提供"接受 / 修正 / 拒绝"三个动作，修正时从 rubric 的档位中选，不开放自由打分。这样每条人工记录都能直接进入一致性统计，而不需要事后编码。
  • 拒绝必须填理由码。理由码（证据不足 / 判定过严 / 判定过宽 / 行为锚歧义 / 其他）会聚合到 rubric 项的维护看板，直接指向"该改哪条锚"。

校准闭环

每个月用人工确认过的记录作为金标准，计算三项指标并写入模型卡：加权 Kappa（QWK）衡量整体一致性、边缘案例一致率衡量最关键区间的表现、项级分歧热力图定位系统性偏差。任一指标跌破阈值的评分项，自动把 ai_authority 下调一档（decide → suggest → extract），直到重新校准达标。这个是自动的，不需要开会决定。

自动降级规则

闸门不只在"上线前"起作用，运行期也需要持续监测。以下任一情况触发自动降级，且降级立即生效、无需审批（事后补报告即可）：

  • 滚动 200 条记录的 QWK 跌破该闸门阈值 − 0.05；
  • 任一站出现 integrity_gap 比例 > 2%；
  • 亚组分数差连续 2 周 > 0.20 SD；
  • 模型或提示词版本变更后未重新校准（系统层面强制：变更即重置为 extract 权限）。
最后一条最容易被绕过

"换了个更好的模型"听起来是改进，实际上会让所有历史校准数据失效。因此系统层面必须把模型版本与权限档位绑定：任何 model_version 或 prompt_version 变化，自动把该能力的 ai_authority 降为 extract，直到完成新一轮人工比对准许回升。不允许"静默升级"——这是可追溯性从口号变成机制的分界线。

三条版本纪律

其一，成绩绑定的是 bundle_hash，不是 station_id。「第 3 站」这个说法在跨年比较时毫无意义——同一站号可能换过三次题。只有哈希能回答"这位考生当时考的到底是哪一版"。

其二，冻结后只增不改。发现错误不改原版本，而是发布新版本并在元数据中记录 supersedes 与 reason。已经考过的场次仍指向旧版本。这是唯一能让申诉站得住脚的做法——若允许原地修改，任何历史结论都可以被事后"修正"。

其三，AI 输出必须携带三元版本戳。model_version + prompt_version + rubric_version。缺任一项的记录视为无效，不得进入成绩计算。这条看似苛刻，实际省掉了未来无数次的"这个分数是怎么来的"。

留存期建议

成绩与评审记录永久保留；音视频按分级留存——L3 场次留存至申诉期结束后 6 个月（通常 2–3 年），L1 练习留存 90 天即降采样或删除。这一策略既满足举证需要，又避免"为了合规把几年的考场录像全存着"带来的隐私与存储双重负担。删除动作本身也要记入 AuditEvent。

一个常被忽略的公平性问题

「人工编辑率过低」应当被视为告警而非成绩。如果评分员对 AI 建议的接受率是 98%，通常不是 AI 太准，而是界面设计诱导了"橡皮图章"——比如默认选中 AI 分数、一键通过、批量确认。这会让复核形同虚设，且在人机一致性指标上呈现出虚假的优秀。健康区间大约是 15%–30% 的编辑率：说明人真的在看，且看得懂。

10路线图与投入

顺序不是按"技术酷炫度"，而是按"证据成熟度 × 风险可控性"。

P0 · 评分副驾 0–3 个月 第一优先

范围限定为离线跑历史录像：选 1 个学科、30–50 个既有考站、近两年的存档视频，不接触在考考生。产出是证据提取链路 + 复核工作台 + 与人工金标准的 QWK 基线。这一步的真正价值不只是省工时，而是顺带产出了后续所有环节需要的标注数据——哪些项 AI 判得准、哪些项天然有歧义，直接决定 P1 的人格卡和 rubric 该怎么改。

放行条件：历史数据上 QWK ≥ 0.70，证据定位准确率 ≥ 90%，人工复核单条耗时 ≤ 90 秒。

P1 · AI SP 练习平台 3–9 个月 第二优先

落地人格卡 + 状态机 + 独立验证器的完整闭环，配套三段式反馈。对象是学生自愿练习，结果不计入任何成绩。这一阶段要刻意把"练得像"和"评得准"分开验收——很多项目在这里把两件事混在一起调，结果两边都调不好。

放行条件：通过 G1 闸门全部指标（事实错误率、人格通过率、延迟、SUS、零安全事故）。

P2 · 模拟 OSCE 与治理闸门 9–15 个月 第三优先

整班模拟考 + A/B 对照（AI 辅助组 vs 纯人工组），同步上线公平性监测与自动降级机制。这一阶段最容易被压缩——因为"系统已经能跑了"。但恰恰是这里的对照数据，决定了机构能否在伦理审查和学术委员会面前站住。

放行条件：通过 G2 闸门；A/B 报告经学术委员会审议。

P3 · 有限高利害 15–18 个月起 渐进开放

仅对行为锚清晰、证据类型为 utterance/action 的非关键项开放 AI 建议权；关键项与全局评分始终人工。同步完成终止开关演练、申诉全流程演练、模型卡公开。范围扩张遵循"一次只放开一档"的原则，每次扩张都要重新走一遍 G3。

放行条件：通过 G3 闸门；连续 3 场零关键项漏判。

如果资源只够做一件事，做 P0。它不需要改造任何现场流程、不接触在考学生、不涉及伦理审查的新增风险，却能在三个月内给出两个硬答案：这套 AI 在我们自己的数据上到底准不准，以及我们的评分表到底有多不可判。第二个答案往往比第一个更让人意外，也更有价值。

11反模式清单

这些做法在演示时都很漂亮，在真实考试里都会出事。

反模式为什么诱人为什么出事
让 LLM 直接产出可用评分表 一键生成整站，看起来效率提升十倍 评分表可靠性恰是 LLM 最弱的环节，指南一致性得分最低、评分者分歧最大。上线后所有争议都会回到"这条锚到底什么意思"
单 prompt 扮演 SP 实现成本极低，Demo 效果惊艳 人格随对话漂移、一问就给全部信息、编造未定义的病史。且这些失效在单次对话里几乎不可见
全量 AI 评分 + 事后抽查 省人力最彻底，报表最好看 没被抽中的错误永久固化；申诉时拿不出证据。抽查比例越低，系统性错判越难暴露
追求全模态（三摄像头 + 音频 + 笔记全上） "数据越全越准"的直觉 成本翻数倍，而三摄像头相对音频的增量主要出现在体格检查类站。多数站用音频 + 笔记已足够，全模态属于为 5% 的场景付 300% 的价钱
同一个模型既生成又评判 省一次调用，架构简单 自我确认偏差：它会认为自己的输出是合理的。必须换模型、换提示、且限制验证器的可见上下文
先上线再补治理 "先跑起来，日志以后再加" 日志与版本戳必须从第一条记录就存在，事后无法补造。没有它们，前面积累的所有效率收益都无法被机构合法采纳
用统一风险等级管所有站 配置简单，沟通成本低 要么对"洗手"这种可自动判定的项过度保护（浪费人力），要么对"共情"这种高歧义项过度放权（制造风险）。粒度必须是评分项
把"人机一致率高"当作唯一成功指标 数字漂亮，容易向上汇报 如果人工只是橡皮图章，一致率会虚高。必须同时看编辑率、边缘案例表现、以及"AI 独立判断被人推翻后谁对"
